# 项目设计方案

作者：谢应江，学号：230010083。方案日期：2026 年 10 月 26 日。

## 项目定位与功能

服务《人工智能系统部署与运维》课程学习者，解决“知道答案却说不清为什么”和错题分散的问题。首期只做 Kubernetes 单选题练习与错题讲解，不做通用聊天平台。教师维护题库、答案与资料；学生独立作答后获取讲解并重练。

本次提供可运行的最小框架，不要求实现完整教学平台。学生可登录、按知识点筛选题目、提交答案、看标准解析、请求讲解和查看个人错误记录。教师从 Django Admin 管理知识点、题目、资料及账号。

## 大模型介入方式

规则层先验证选项并比较标准答案，保存答案和解析快照。讲解服务按题目所属知识点读取最多 3 条已发布资料，将题目、学生选择、程序判分、标准解析和资料片段作为数据发送给模型。模型输出中文概念解释和复习建议，不参与客观题最终判分、不执行服务器命令。

默认 mock 模式明确标注未调用模型。API 模式连接百炼兼容接口，失败则显示标准解析降级。学生身份信息、密码、云端密钥和完整成绩历史不会发送给模型。模型文本经 Django 模板转义，资料来源由服务端选择并展示，不将其声称为逐句事实核验。

当前是“知识点精确筛选 + 资料辅助生成”，尚无向量数据库或语义相似度检索，因此不宣称完整向量 RAG。后续资料规模增大时才引入切片、Embedding 和召回评估。模型按服务接口封装，可更换供应商，不需要在三个 Kubernetes 节点上安装大模型。

## 数据来源与关系设计

示例题和摘要由本项目自编，参考 Kubernetes 官方文档；真实课堂内容由教师审核后录入，需保留来源、适用版本和授权范围，不默认抓取付费教材。示例不含真实学生记录。数据库表及关系见 DATA_MODEL.md。

学生与作答是一对多；知识点与题目、资料均为一对多；题目与作答一对多；作答与讲解一对一。错题本是当前用户 is_correct=False 的作答查询，避免维护两份错误状态。题目变更不会覆盖已保存的答案与解析快照。

## 部署设计

开发模式使用 Python 3.11 和 Django 5.2 LTS；API 模型独立于 Web 服务。镜像包含代码、依赖和已收集静态文件，不包含数据库与密钥。演示部署在 1 个控制平面和 2 个工作节点的 Kubernetes 集群，以独立命名空间、Deployment、Service、Secret、ConfigMap 和 PVC 组合。

SQLite 数据存放在 node2 的本地 PV，应用单副本，maxSurge=0、maxUnavailable=1。这种部署便于课程演示并保留 Pod 替换后的数据，但不提供节点故障自动迁移或无中断更新。正式多用户环境迁移 PostgreSQL/MySQL 与共享存储，保持会话密钥一致后再扩副本；也需接入 HTTPS 和更严格的限流。

## 运维设计与可行性

检查 /healthz/、Pod Ready、HTTP 错误、模型超时率、token 使用量、持久盘剩余空间。SQLite 使用 Python backup API 获取一致性快照，离线安全保存，不提交代码仓库。首次上线完成备份恢复演练。数据库 schema 变更先备份并检查向后兼容；rollout undo 只恢复 Pod 模板，不回退外部数据。

可行性来自范围控制：题目判分不依赖模型，断网可演示标准解析；SQLite 降低部署复杂度；API 调用免去 GPU。首期以 8 道种子题验证流程，后续扩充教师审核题库，不以少量题目证明教学效果。先进行真实 API 抽检和小班试用，再评价讲解质量和并发容量。

## 验收目标

登录后能完成练习、规则判分和错题复习；学生不能读取他人作答；未发布资料不能进入上下文；API 失败后标准答案与判分不变；顺序重复请求复用已保存讲解；页面显示来源和演示/模型/降级状态。目标测试集 30 道教师审核题，抽检概念准确率至少 90%，此项是未来验收指标，不是本次已测结果。

并发目标先按 10 个活跃学生规划，模型调用等待可能达到 20 秒，单 Gunicorn worker 只适合低并发演示。公开试用前需加入任务队列、幂等锁、限流与压力测试，不能从 requests/limits 推导真实并发能力。
