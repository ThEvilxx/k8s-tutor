# 大模型调用及评估

## 输入与输出

服务端给定系统角色，用户消息只包含 JSON 数据：题目、选项、学生选择、标准答案、程序判分、标准解析、同知识点审核资料。不将账号、姓名、密码和 API Key 放入提示词。

Prompt 要求只解释、不改判、不执行命令、缺少依据时说明。模型文本仍可能错误，页面优先显示标准答案和教师解析。资料链接由服务端记录，代表本次提供的资料，不保证模型每句话都有来源支撑。

## 演示模式和 API 模式

LLM_MODE=mock：本地生成带明确标签的标准解析，不联网、不产生模型调用费。
LLM_MODE=api：通过 urllib 请求百炼 Chat Completions，默认 qwen-plus、enable_thinking=false、temperature=0.2、输出上限 800 tokens、20 秒超时。LLM_BASE_URL 和密钥地域匹配，换供应商需适配非标准参数 enable_thinking。
调用失败：不自动无限重试，保存 fallback 状态和标准解析，不展示凭据及底层响应原文。已保存 fallback 不自动再次付费请求；如需重试，由教师处理或后续补充明确按钮。

## 资料检索边界

当前只按知识点筛选最多 3 条已发布摘要，每条最多 1200 字符。不是向量 RAG。示例数据是自编题和摘要，正式课程资料需要人工审核、出处和版本管理。若未来加入向量检索，应独立评价召回率和来源正确率。

## 测试计划

本地自动化验证判分不受模型输出影响、API 超时降级、来源过滤、权限隔离、文本转义和顺序讲解复用。真实模型调用未在本次交付中执行。
后续取 30 道教师审核题，每题准备至少 2 个常见错误选项；教师逐项评估概念、针对性、来源一致性和建议可执行性。目标概念准确率>=90%，P95 耗时<=20 秒，均为待测指标。成本从模型 usage 统计，若供应商没有返回 usage，记录 0 不能视为免费。
